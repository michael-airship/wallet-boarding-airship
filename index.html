The lifecycle

The flight and the passenger are modelled separately.

This lets one operational update reach every linked boarding pass.

Start with two templates. The template controls design and platform settings, and the API payload supplies the real flight and passenger data.

Solution architecture

Airline systems stay the source of truth.

PNR, check-in and flight operations feed a platform-neutral model. Airship turns that data into signed, hosted and updatable wallet passes.

Airline systems
Flight operations Times, gate, terminal, status, route
PNR & check-in Name, seat, cabin, group, barcode
Airship Wallet Managed layer
TemplatesBrand and platform configuration for Apple and Google
Flight entityShared operational record referenced by many passes
Adaptive LinksPassenger personalisation and device-aware routing
Pass deliveryGeneration, signing, hosting, registration, and updates
Passenger wallets
Apple Wallet Semantic boarding pass and supported live experiences
Google Wallet Google boarding pass rendered from its template

Flight-level update

Change shared operational data once.

  • Gate or terminal change
  • Boarding or departure time
  • Flight status
  • Propagates to linked passes

Passenger-level update

Change only the affected passenger object.

  • Seat or cabin assignment
  • Boarding group
  • Barcode or confirmation code
  • Targets the Adaptive Link external ID
More than boarding passes

The same wallet platform can support the wider customer journey.

Airship supports seven pass types. For Emirates, the clearest next use case is a persistent Skywards loyalty card that can sit alongside the trip-specific boarding pass.

Emirates Skywards in Apple and Google Wallet

A loyalty pass gives members quick access to their identity, tier and membership number without opening the app.

  • Keep tier, points and member details current through pass updates.
  • Use one Adaptive Link to serve the correct Apple or Google pass.
  • Connect the Skywards card with a boarding pass in Google Wallet using Auto Linked Passes.

Build vs. Airship

The same capabilities, two different ways of getting them.

Airship does not replace flight operations or check-in. It removes the platform plumbing between those systems and the passenger’s wallet.

01

Apple semantic tags without duplicate data

Airship maps standard boarding-pass fields to iOS 26 semantic tags. The baseline API payload does not need a second copy of the data.

See semantic-tag support ↗
02

Boarding pass and Skywards card together

Auto Linked Passes connect an Emirates boarding pass with the traveller’s Skywards membership card. Google Wallet groups both without a second save or install step.

See Auto Linked Passes ↗
03

One link for a multi-flight journey

Multi-Pass Adaptive Links bundle up to 10 passes into one URL. This works for connecting itineraries, as well as family or group travel.

See Multi-Pass Adaptive Links ↗
